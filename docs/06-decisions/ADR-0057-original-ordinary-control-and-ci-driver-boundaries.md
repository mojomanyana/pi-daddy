## Ordinary original lifetimes

The actual grants extension associates its original ExtensionAPI/session objects with one process-local
controller. `ordinaryChildrenFor(originalHost)` explicitly enables capture. The original shared executor
wrapper retains its own AbortController, combining—not replacing—the caller/lease cancellation path.
Public delegate/all/chain still use their original plan, grant decision, deadline, executor and caller
promise. No PID, title, logical child position, pane or persisted string reconstructs a kill capability.

Default callers do not allocate the bounded registry. Any execution before opt-in leaves a monotone
coverage gap: later empty rows cannot certify quiescence. Opted-in sessions retain at most1024 occurrence
records/requests; capacity refusal releases the newly prepared workspace through the existing finalizer
without displacing a primary error. There is no eviction, restart, refund, crash takeover or cleanup API.

Exact cancellation binds the original controller digest, monotone revision and actual execution/parent/
tool-call identity, with separate whole-request authority. CAS and original abort request are synchronous;
a duplicate returns its original result even after revocation/completion, never another abort. Abort request
is NOT observed completion. The original caller still owns/receives success, cancellation, failure and
retention. A failed terminal observation is separately `control: failed`, even with successful worker output;
executor throw is unknown. No registry state is reconstructed after process loss.

The existing host journal remains the ONLY durable dashboard control transport. Optional ordinaryDigest
binds the original port; `ordinary-cancel` routes approved exact requests through the existing CLI action
handler. Complete final host bytes with a failed acknowledgement remain failed/unknown and never replay an
effect. Copied interfaces reject. Presentations additionally refuse known active/unknown/unretained ordinary
lifetimes. This is not an atomic live TUI pause, authenticated human identity or cross-store transaction.

## Broader bounded P01 application

Opt-in `intent-request-v2` / `revise-selection` appends exact successor revisions without inventing a scope
revision when only other selected content changes. Existing P01 builders/resolver, request digest/authority,
resource lock, original-permit quiescence, pending barrier, append-once and explicit reconciliation apply.
The v1 schema and actions are unchanged. Existing readers refuse the new action rather than reinterpret it.
The v2 schema embeds exactly the same P01 definitions, not alternate validation logic.

Same entity inventory, owners, scope membership, parent/dependency topology, exact policy references and
policy content stay fixed. Permissions may not expand. Every changed selected revision must directly
succeed the previous selected revision, with complete selected closure and at least one real successor.
Goal/obligation application through the actual dashboard is exercised. New entity/topology changes and
opaque policy changes remain separate A work; their safety cannot be established by digest equality alone.
No grant or acceptance is transferred; original snapshots/receipts remain retained.
