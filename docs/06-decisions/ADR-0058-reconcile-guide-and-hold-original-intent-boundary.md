# ADR-0058 — Reconcile actual guide scope and hold the original ordinary intent boundary

Status: bounded local implementation, not published/accepted
Date: 2026-09-08

Root cleared exact6212 publication and required original-guide reconciliation before further expansion.
That one publication precedes this source. The original review/guide remain immutable; this is not a new
review or approval. Current and frozen guide bytes match. No peer, model/live, install or native-approval work.

## Reconciliation rather than invented scope

P01 requires generic versioned entities/dependencies, provenance and exact revision-bound acceptance.
Those builders/projections and all five revision acceptance cases already exist. P05 asks for authorized
scope revision, priority, recorded alternative, pause and cancellation, with safe-boundary/CAS/readback.
The6212 adapter added actual non-scope successors without a fictitious scope change and original ordinary
cancellation. P15/guide rule7 explicitly preserve active pins and subsequent-order policy adoption, allowing
explicit migration exceptions; existing fixed-policy activation/rollback/unstarted migration address that.

Neither the guide nor the original review specifies a generic entity/topology CRUD editor or a rule that
makes arbitrary opaque policy content safely mutable. Earlier broad remaining-A wording is not permission
to invent one. Such extensions remain unsupported and need concrete semantics/scope; they are not declared
impossible B, not silently waived, and no original review finding is closed by this reconciliation.

## Concrete existing P05 omission reproduced

With an actual attached ordinary controller holding a live public delegate, but zero resource reservations,
the6212 dashboard immediately applied a v2 successor. The negative compared actual P01 bytes while the
original child was still alive. This violates P05's existing busy-child/safe-boundary obligation within
that attached route. It is distinct from adding entity kinds or policy semantics. Original P06/resource
permit waiting was already real and is retained; it did not account for this ordinary child.

## Decision

Use a bounded admission hold on the EXISTING original ordinary controller, plus a pending transport entry
in the EXISTING host journal. No new decision/control database, runtime observer or scheduler is introduced.

- Host AND native whole-request authority must pass before taking the original hold. Missing original
  ordinary port refuses application, never reconstructs a boundary from a digest/PID/pane/string.
- The hold prevents new ordinary execution at the shared original executor admission seam. It does not
  abort/change an already running caller, its primary result, lease signal or production deadline.
- A busy ordinary request records its exact native digest/ID as pending without applying P01 or fabricating
  a resource reservation. Historical pending transport is visible; it is not current application authority.
- Settlement/status/reopen does not auto-apply. A separately approved intent-reconcile rechecks the original
  ordinary boundary and existing native resource state. Only an exact retained pending direction can first
  enter the native request path from reconciliation; otherwise native reconciliation keeps its old meaning.
- Holds remain across asynchronous native append/sync/application, eliminating a check-to-launch gap. Native
  resource pending state also retains the ordinary hold until the ORIGINAL permit settles and explicit
  reconciliation succeeds. Concurrent native CAS and append-once validation remain unchanged.
- Only an explicit native applied/not-applied receipt followed by successful final host acknowledgement
  releases this operation's original hold. Failed/unknown acknowledgement retains it, even with complete P01
  effects/host bytes. Duplicate/read-only reconnect never releases or replays effects. Other holds survive.
- Holds are bounded32 and change the ordinary controller revision. No expiration/takeover/unlock/recovery is
  inferred. Late opt-in/unretained or failed/unknown ordinary lifetimes still cannot certify quiescence.

Unattached native budget APIs retain their own supported resource-boundary scope. This does not establish
atomic arbitrary live TUI steering or application to untracked workers. Do not downgrade to an older host
writer for new pending ordinary operations: older source lacks this safeguard. Source rollback is not
permission to erase journals, release unknown holds, refund attention or resume an uncertain lifetime.

## 2026-09-11 amendment — distinguish settled observation notes from unavailable ownership

Review finding 3984194288 reproduced a permanent hold: the executor reports non-strict terminal lifecycle
and lease-record failures beside an otherwise known-settled child, but the ordinary port treated that note
as unavailable execution ownership. Intent then installed a hold that no reconciliation could satisfy.
The decision is narrowed, not weakened: best-effort post-execution observation failure remains visibly
`control:failed` but its execution boundary is settled. Required control failure, unknown ownership and
late/unretained coverage still cannot certify quiescence. Those already unavailable states now refuse before
a hold is installed, preserving fail-closed intent application without blocking every unrelated future
ordinary admission. Busy/live rows still take and retain the intentional pending hold, and failed/unknown
host acknowledgement after an attempted effect still retains it.
