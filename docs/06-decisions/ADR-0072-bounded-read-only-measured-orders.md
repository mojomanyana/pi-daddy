# ADR-0072: Bounded read-only measured orders recover by acknowledgement, not ownership transfer

Status: candidate

`measured-order-v1` composes the opt-in measured-session route into a persistent dependency DAG. An order has at most eight nodes and three predeclared attempts per node. Every attempt fixes one Codex Sol/Terra model, thinking level, prompt, deterministic output contract, token request, retained-output bound, deadline and termination grace. Exact output digest remains available for reproducible jobs. Free-form JSON jobs instead declare bounded required fields/arrays and an exact digest of selected source-derived projection fields, so prose may vary while objective source fidelity remains deterministic. The original resource budget must have enough attempt, input and concurrent allowance for the entire order; unknown attempts can therefore remain charged without inventing capacity.

One `advance` claims and executes one eligible attempt. Dependencies become eligible only after the declared deterministic contract passes. When an attempt opts into dependency input, each satisfied predecessor's complete retained output is appended to the fixed prompt in a labelled sealed block carrying the newly observed output SHA-256; the creation check charges worst-case predecessor retention bytes rather than assuming a prewritten answer. A dependent attempt may request actual predecessor outputs; the coordinator appends each complete retained output with its newly observed SHA-256 in a sealed labelled block. Worst-case dependency bytes are charged against the order's frozen input allowance before creation. The dependent therefore consumes the actual prior artifact, not a pre-written expected answer. Claims/results are canonical, hash chained and fsynced in a pinned owner-private journal. Every locked read/append uses a no-follow descriptor whose fstat matches the retained device/inode/mode/link identity, with a linked-path recheck before writes. A controller reopened with a different owner reports an unfinished foreign claim as unknown and never relaunches it. Recovery requires a separately authorized acknowledgement bound to the exact claim owner/digest. Acknowledgement consumes only that declared schedule position; it never settles, refunds or adopts the original resource permit. The next attempt uses retry parentage only when the original reservation actually exists, covering a crash between schedule claim and resource reservation.

The route remains read-only/no-tool because all effects pass through `runMeasuredAgentSession`. Results preserve measured evidence and diagnostics; acceptance remains not assessed. This does not add shell autonomy, recover a process handle, infer human approval or call Pi catalog cost a subscription charge.
