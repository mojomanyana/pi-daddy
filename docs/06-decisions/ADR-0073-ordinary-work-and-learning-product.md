# ADR-0073: Ordinary work and learning use existing owners, not protocol authoring

**Date:** 2026-09-14

**Status:** Accepted implementation direction; candidate awaiting independent end review

**Driver:** the user's full-product delivery proposal: outcome-first panel, normal multi-task/model/effort
setup, retained learning choice/trust/adoption/outcome actions, then one independent end review.

## Decision

1. Make `renderDailyView` the concise outcome/state/active-agent panel. Preserve the former diagnostic
   renderer as `renderDailyDetails` and keep historical contract fixtures unchanged. Numbered human
   actions bind the exact displayed host tip and request digest; a repaint never reassigns a number.
   Native acknowledgement is not inferred from an unrelated historical receipt.
2. Author one to eight task DAGs through `/grants work`. Reuse P01 revision/snapshot builders and selected
   declared-work state; retain instruction/presentation bytes separately in owner-only project files.
   This deliberately changes the old single-declaration text-retention choice, not governance ledger
   content. Existing declarations without retained labels remain readable, honestly unnamed.
3. Run a finite DAG through `runOneDelegation`, the original session/executors, grant/approval/timeout
   guards and subtree budget. Split the existing budget across all planned tasks, bound concurrency,
   preserve complete bounded predecessor handoffs/results and do not retry. Pause holds pending work;
   cancellation waits for originals. Explicit per-child obligation binding avoids shared-state mutation.
   Recheck pinned selected work at original admission, including after an approval delay. No universal
   ordinary-model usage cap or hostile-process containment is added.
4. Scope/alternative/priority changes traverse the existing daily intent/dispatch owner. New topology
   needs a new work selection/host. Active orders never rebind. A scope change prevents the old order's
   remaining children from starting; original completed evidence remains intact.
5. `/grants learning` composes the **already loaded harness bridge** and its public workspace/wizard.
   No new transport, evidence database or calibration/quality policy. Use the raw P01 selected snapshot
   digest, archive root, population and author as explicit connection identity. A mismatch requires an
   explicit new connection. Reuse original configured trust/attention, with a separate host journal;
   unconfigured trust stays silent/bootstrap, not calibrated. Deliberate review is distinct from earned
   automatic closing exposure.
6. Add an `ordinary-work-policy-v1` registry profile for exact model/effort changes on unchanged scoped
   task IDs/definition names. It does not pin definition files or tree state; original digest/approval
   checks still apply. Preserve the existing fixed-policy/factory-order contracts unchanged (including
   their different scope fingerprint). Reuse control journals, core adoption/rollback predicates and
   independent `FactoryAuthority`. Candidate bytes, independently confirmed current eligibility, exact
   activation consent and the actual registry observation remain separate. Quality choice is not authority.
7. Author the missing adoption binding using validated public `comparisonContext`, `hypotheses`,
   `decisionStatus`, `reveal` and `linkComparisonContext`, then invoke existing `prepareAdoption`.
   `reveal().manifestId` is the actual intervention identity. Never invent an origin or read private journal
   structure to reconstruct it. Link real registry receipts; readback recovery never repeats the effect.
   Future runs pin profiles and revalidate independent eligibility. Later output linkage uses actual
   retained run bytes/pins plus explicit independent outcome consent; acceptance stays absent.

## Consequences and validation boundary

The short installed guide and current requirement register are packaged. Ordinary Principal/runtime skill
workflows remain generic; no Principal definition or policy is hardcoded. Invalid profile/state/evidence
refuses rather than falling back. Missing calibration/preference/qualifying comparison/later efficacy is an
explicit state, not a fabricated success.

Focused regressions accompany the implementation. Narrow type/build/check receipts belong to the delivery
campaign; independent whole-change review, broad suites, installed cross-package/Herdr validation and
release remain coordinator gates. No live experiment, human acceptance, calibration, activation or
production improvement is established merely by adding these paths. ADR-0008/0012/0016 and the frozen
published ledger/retention contracts remain the safety boundary.

## 2026-09-14 PR52 review repair amendment

Sol's independent review requested changes (SOL-1/2/3), so the earlier candidate is not approved.
A manual host stop now uses the original action gate and refuses outstanding pause/pending/unknown
control without dropping the host/socket or releasing a hold. Explicit acknowledged resume precedes stop;
a denied resume cannot clear a prior pause, and a lost final resume acknowledgement retains admission.
Final owner-session disposal only disconnects and prevents reuse of that session wrapper; it never claims
control reconciliation. This is separate from manual host replacement, not a forced-resume escape hatch.

Resolve a rollback preview by pure validated registry replay. Final consent shows the immutable restore
digest and all retained task/model/effort rows, including nested restoration to a non-baseline profile.
No authority or rollback write is produced by preview or a declined confirmation. Original activation
and inspect views already supply applied/request/last-change/full-receipt proof; the producer keeps those
identities on learning recovery. The harness must validate them (SOL-2), not infer activation from candidate
state. Fixed-policy contracts are unchanged and bare legacy views are not upgraded into proof.

Focused stop/race/acknowledgement and rollback/activation/recovery regressions accompany these repairs.
The four PR52 CI failures used retired labels, including an opaque ID removed from cancellation labels;
assertions now target current labels and exact displayed cancellation bindings, retaining stale refusal,
75-sibling availability, original-handle effects, and sibling isolation checks. Fresh check/source identities
belong in `producer-evidence/REPAIR-READY.json`; prior READY/review receipts remain untouched. Independent
repair review, broader CI and installed/live qualification remain coordinator gates.
